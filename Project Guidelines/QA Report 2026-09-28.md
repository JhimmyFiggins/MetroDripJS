# QA Report: 2026-09-28

## Executive Test Summary

**Release recommendation: HOLD.** The supplied stack, entry points, tools and peak threshold were placeholders, so this pass discovered the repository's actual environment and used a bounded local load target. This is not a 5,000-user or production-capacity certification. Existing release blockers in the [previous QA report](QA%20Report%202026-09-27.md) remain until separately resolved and verified.

Environment: Windows, Python 3.15.0b2, Django 5.2.16, Node 24.16.0. The current topology is Expo/React Native for customers, static HTML/CSS/JS staff consoles, five Django/DRF services, and a Python development gateway. The intended deployment uses Nginx and PostgreSQL 16; the Docker daemon is unavailable here. The load run instead launched six owned loopback processes against five newly migrated, disposable SQLite databases. It issued only public reads and expected unauthorized reads; no persistent application database, live account, or purchase was touched.

## Residual Gaps & Recommendations

- **HOLD:** Staff-console authentication, untrusted demo operational data during API failures, and automatic outbox dispatch/reconciliation remain open release defects from the previous QA report. The Add User keyboard defect is narrowly resolved; form length/phone validation and comprehensive focus/contrast/zoom audits are not.
- A real peak concurrency/throughput and acceptable p95/p99/error thresholds have not been specified. Set those alongside representative data volumes and a production-like stack before a capacity verdict.
- PostgreSQL transaction races, unique-key contention, index/query plans, and pool saturation were not measured because Docker is unavailable. SQLite and development-server timings do not substitute for PostgreSQL/Nginx load tests.
- Existing automated suites exercise selected authentication, validation and retry boundaries, but this pass did not prove exhaustive coverage of every route or arbitrary malformed payload and timeout combination.
- Python 3.15.0b2 is a prerelease runtime in this Windows check. Repeat release gates on a supported production interpreter rather than assuming compatibility from these results.
- CPU throttling, process RSS trends, memory leaks, thread counts, sustained-soak behavior, and native-client traffic were not measured. `psutil` and `k6` are not installed; `adb devices -l` listed no devices. No CPU/memory or native stability claim is made.
- The browser test checks document overflow and one dialog keyboard sequence with mocked API responses. It does not exercise real checkout forms, general keyboard/focus/contrast/ARIA behavior, screen readers, 200% zoom, or browser-to-live-API flows; Firefox/WebKit, native rendering, external provider timeouts, and deployed TLS/network policy require separate controlled environments. See the previous QA report for the still-open coverage matrix.
